ANetRLogin v0.2.1 - Configuration
=================================

DESTINATION FORMAT
------------------

    [destination ID]
    name=Friendly Name
    host=hostname.example
    port=513
    client_user=...
    server_user=...
    term=ansi/115200
    expect_ack=1

Available caller macros:

    %USER%       BBS user name
    %ALIAS%      BBS alias / handle
    %PASSWORD%   BBS password

These macros may be placed in either RLogin identity field because different
RLogin servers use RFC1282's client-user and server-user fields differently.


SYNCHRONET-COMPATIBLE LOGIN
---------------------------

The tested working mapping for A-Net Game Server / Synchronet is:

    [destination ANETGAMES]
    name=A-Net Game Server
    host=game.a-net-online.lol
    port=513
    client_user=%PASSWORD%
    server_user=%USER%
    term=ansi/115200
    expect_ack=1

This is PASSWORD FIRST, USER SECOND.

Do not reverse these two fields for a Synchronet-compatible target unless
that server is specifically configured to expect something different.

Synchronet rlogin.js provides a -p mode for passing the caller identity and
plain password. ANetRLogin v0.2.1 provides the equivalent capability using
%PASSWORD%.

Synchronet also provides -h for a salted/hashed password. ANetRLogin v0.2.1
does not yet implement Synchronet's hashing format.


OTHER SERVERS
-------------

Because the fields are configurable, another server might use:

    client_user=%PASSWORD%
    server_user=%ALIAS%

or:

    client_user=%USER%
    server_user=%ALIAS%

Choose the mapping required by that destination.


MULTIPLE DESTINATIONS
---------------------

ANetRLogin supports up to 32 configured destinations.

Example:

    [destination ANETGAMES]
    name=A-Net Game Server
    host=game.a-net-online.lol
    port=513
    client_user=%PASSWORD%
    server_user=%USER%
    term=ansi/115200
    expect_ack=1

    [destination OTHERBBS]
    name=Another BBS
    host=bbs.example.com
    port=513
    client_user=%USER%
    server_user=%ALIAS%
    term=ansi/115200
    expect_ack=1

Launch with:

    ANETRLGN.EXE ANETGAMES

or:

    ANETRLGN.EXE OTHERBBS

Restart ANETRLB.EXE after changing ANETRLGN.INI.


MULTI-NODE
----------

ANetRLogin supports up to 10 BBS nodes through one bridge.

Each node with a separate DOOR.SYS directory needs an ANETRLGN.CFG pointing
BBSDir to that node's drop-file directory.

All nodes must use the same DoorDir so the single ANETRLB.EXE bridge sees
every node's IPC files.

A-Net Online live Spitfire examples:

    Node 1:
        BBSDir C:\SF\SFEXTEN2
        DoorDir C:\SF\ANETRLGN

    Node 2:
        BBSDir C:\SF2\SFEXTEN2
        DoorDir C:\SF\ANETRLGN

Node IPC naming:

    ARL01.*  Node 1
    ARL02.*  Node 2
    ...
    ARL10.*  Node 10

Two simultaneous Spitfire nodes have been live-tested successfully through
one ANETRLB.EXE bridge.


SECURITY
--------

The destination ID is an allowlist key. Callers do not supply arbitrary
hostnames or ports.

The bridge must never display or log an expanded %PASSWORD%.

RLogin is plaintext. Using %PASSWORD% transmits the caller's password
unencrypted over the network.

Use trusted destinations and private/VPN paths where practical.
